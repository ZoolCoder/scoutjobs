= Dashboard
:description: What each page of the localhost dashboard shows and what you can do on it.

[source,console]
----
$ scoutjobs serve                     # http://127.0.0.1:7070
$ scoutjobs serve --addr 127.0.0.1:8080
----

One Go binary, SQLite, HTML templates, no JavaScript, no external assets, strict Content-Security-Policy. Light theme by default, `theme: dark` or `theme: auto` in `config.yaml`, and a switch in the sidebar that overrides per browser. The pages have no login, so keep it on localhost (see xref:security.adoc[]).

== Pages

[cols="1,3"]
|===
| Page | What it is for

| Overview
| Your next best move, the funnel, applied this week against `weekly_apply_target`, follow-ups due, stale jobs, upcoming interviews, activity streak.

| Pipeline
| One column per open status. *Due this week* keeps only open jobs with a deadline within 7 days or a follow-up due; the search box filters company, title and tags. Every card opens the job and can be dragged onto another column, or onto the closing stages shown below the board while dragging. *Add job* opens a form with the same fields as `scoutjobs job add`; paste a posting URL from Greenhouse, Lever, Ashby, Workable, SmartRecruiters, Personio, Recruitee or BambooHR into *Fill from a posting URL* and the form is filled, description included, for you to check. An existing company and title is updated, not duplicated. Each card has one-click buttons for the stages that follow (`new` offers ranked, drafted, skipped; `applied` offers interview, rejected, no response, withdrawn) and a *more* disclosure for any other status with a reason. See xref:pipeline.adoc[].

| Job
| Everything about one posting: score and fit notes, contact, tags, notes, events, interviews, the *Get selected* kit (tailored resume, cover letter, ATS check at 70 or more, e-mail draft), the *Ready to send?* panel with the seven quality gates and what blocks, and the evidence table from `fit-review.json` with a veto callout when one is set. A vetoed job shows a `veto` badge instead of its gauge on the pipeline board. Each file in the application folder opens in the drafts viewer (`.md`, `.txt`, `.json`, `.eml`). A `mailto:` link opens your own mail app with the subject and body prefilled.

| Search
| The same sources as `scoutjobs search`: queries, boards (`greenhouse:stripe`, a careers URL such as `https://jobs.lever.co/netlify`, `rss:https://...`) and the remote aggregators including the Hacker News "Who is hiring" thread, prefilled from `search_queries`, `search_boards` and `search_remote`. Results list company, title, place, source and date with an *Add* button each, or *Search and add all* tracks every hit as `new`; a posting already in the pipeline shows its stage instead of the button. Postings are stored as text and never followed.

| Interviews
| Scheduled and past interviews with prep status, plus the mock sessions and their scores.

| Learning
| Skill gaps found by `upskill`, ranked, with hours tracked.

| Preferences
| What you stated and what `learn-preferences` learned, with confidence and the decisions behind each.

| Profile & CV
| `profile.md`, the files in `cv/`, the latest CV check with both scores and the gap list, and the history of checks.

| Reviews
| The files `weekly-review` writes to `reviews/<YYYY-WW>.md`, newest first, next to the funnel as it stands now, applied this week against target, follow-ups due and stale count.

| Activity
| Every event: job added, status change, note, decision, CV check, e-mail draft or sent, file written through the API.
|===

== Drafts viewer

`/jobs/\{id}/files/\{name}` renders a text file from the job's application folder: the posting, the tailored resume, the cover letter, the e-mail draft, research, the prep sheet. Drafts (`.md`, `.txt`, `.json`) open in a textarea: edit, save, and the agent sees the new text on its next read; the save logs `draft:edited`. `.eml` files are read-only. Binary files (PDF, DOCX) are listed but not rendered. When `resume.md` exists, the Files panel offers "Export resume.md as PDF", which writes `resume.pdf` next to it and logs `cv:export`.

== JSON API

The same server answers `/api/*` with JSON, for n8n, cron and agents that cannot run the CLI. Set `api_token` and the API requires `Authorization: Bearer <token>`; the pages stay open. See xref:api.adoc[].
